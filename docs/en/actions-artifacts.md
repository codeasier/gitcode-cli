# GitCode Actions artifacts

```sh
gc run artifacts RUN_ID -R owner/repo --page 1 --limit 20
gc run download RUN_ID -R owner/repo --artifact-id ARTIFACT_ID --attempt 1 --commit HEAD_SHA --output ./artifact.zip
gc run download RUN_ID -R owner/repo --name build-package --attempt 1 --commit HEAD_SHA --output ./artifact.zip
```

- `run artifacts` lists one page for the observed run ID and verifies its workflow, head commit and current attempt before and after listing. The API identifies an artifact's run, not its attempt. After a rerun, `artifact_attempt` is null. The list requires all documented fields, including the three nullable timestamp fields. A malformed artifact row invalidates its page, even if it is unrelated to a requested name. The list contains no download links.
- `run download` saves one raw ZIP. Specify exactly one artifact ID or one exact name, plus a full head commit SHA and an explicitly observed first attempt. The command does not pick the latest run, extract entries, or overwrite anything. Downloads from later attempts are not enabled because the API has no per-artifact attempt field. The workflow, run, exact artifact ID, byte size and SHA-256 must agree across the documented list and detail endpoints, and the download must match the size and digest. These are provider metadata checks, not cryptographic provenance attestations.
- `--name` is a literal, case-sensitive match. Use one nonempty printable name of up to 1024 characters. It must be the only match across the complete run listing (at most 20 pages of 100). The CLI does not use the provider’s fuzzy name filter. Before installing a name-selected ZIP, it checks the complete listing again and rejects any observed change to artifact membership or metadata. These checks compare observations, not an atomic server snapshot. If names collide, use the artifact ID. Repeated selectors, patterns, batch downloads and routing through the gh proxy are not supported.
- The output must be a new `.zip` file in an existing user-owned directory not writable by other users or groups. Download requires POSIX directory-descriptor support and rejects symlink path components. It checks the path without creating files, then opens a private staging file only after verifying the initial run, list and artifact detail. Installation is an atomic no-overwrite link in the original directory. The command checks that the requested directory path still identifies that directory before staging and around installation. These are checks, not an atomic pathname guarantee. If it detects a change after linking, it reports failure and may leave the verified archive in the original directory rather than risking removal of another writer’s file. On incompatible platforms use `run artifacts` for evidence and the provider's UI for downloads.
- The fixed GitCode Actions endpoint returns a signed transfer location. Storage requests and redirects use no reusable GitCode token, cookie or environment proxy. They use only HTTPS on port 443 to public addresses for exact GitCode/AtomGit provider hosts. This includes `actions-artifacts-cdn.atomgit.com`, [observed in a real provider redirect](https://github.com/codeasier/gitcode-cli/pull/208#issuecomment-7126164981), but does not trust other subdomains by suffix. Unknown destinations fail closed. Transfer is capped at 512 MiB. If the provider uses an unrecognized storage host or does not return a size or digest, retrieve the artifact through the provider UI rather than overriding verification.

Provider contracts: [workflow run attempts start at 1 and advance on rerun](https://docs.gitcode.com/en/docs/help/home/org_project/pipeline/action-development/runtime-environment-variables/), [run detail and observed attempt](https://atomgit-api-doc.atomgit.com/en/17.actions/256.get_pipeline_run_details.html), [list artifacts for a run](https://atomgit-api-doc.atomgit.com/en/17.actions/262.list_specific_run_artifacts.html), [artifact details](https://atomgit-api-doc.atomgit.com/17.actions/263.get_artifact_details.html), [artifact ZIP redirect](https://atomgit-api-doc.atomgit.com/en/17.actions/265.download_the_specified_artifact.html).

The client applies a 30-second socket inactivity timeout and checks its 300-second
transfer budget between operations. That budget is not a hard wall-clock bound
during DNS or a blocking header/chunk read. Only a fully verified ZIP is installed.
