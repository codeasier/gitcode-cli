# PR 人员操作

GitCode 的两个角色不等价：`pr create -a/--assignee` 与 edit 的 assignee 选项管理原生**审查人**（`assignees`）；`-r/--reviewer` 与 edit 的 reviewer 选项管理**评审人**（`approval_reviewers`）。指派人员不等于提交批准。

输入使用账号 login、逗号分隔列表、重复 create 选项或 `@me`，不接受昵称、团队或 URL。同一角色同时添加和移除同一账号会在写入前拒绝。dry-run 将人员副操作单独列在 `people_operations`，不会声称通用创建接口可直接应用这些字段。

创建 PR 只调用一次，随后确认 PR 序号、ID 和人员列表，再调用独立人员端点。edit 在任何写入前预检，纯人员 edit 不发送空 PATCH。已添加、已移除的目标是只读 no-op；新增评审人使用 `add: true`，不覆盖其他人。读回检查目标结果、PR/成员身份及预检中无关人员的保留，允许并发新增人员。

这些请求不是事务。失败或读回无法确认时退出非零，提示 PR 可能已创建或部分更新；不会自动重复创建、人员写入或回滚。重试前先查看该 PR，失败退出不代表创建已回滚。权限、仓库策略及并发移除仍可能导致确认失败。

官方端点、来源链接和验证范围见 [英文说明](../en/pr-people.md)：assignee 删除参数位于 **query**，reviewer 删除参数位于 **JSON**；两者不可混淆。离线严格 HTTP 合同使用 `.invalid` 地址和合成凭据，需通过 CLI 与 MCP 源兼容 CI，但不代表线上权限验收。以后获授权的隔离沙盒验证应使用专用账号，保留已有两类人员，检查增删、`@me`、拒绝及读回，仅清理自建夹具，不隐含批准、合并或生产操作。
